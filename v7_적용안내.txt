찰픽 v7 적용 안내
작성일: 2026-10-23

이번 묶음은 GitHub 웹 업로드용 97파일입니다. 이전 100개 초과 선택은 커밋하지 말고
업로드 화면을 새로 연 뒤 압축 해제한 내용물을 저장소 최상위에 한 번에 올리세요.
전체 개발 원본의 테스트·일회성 조사 도구와 미사용 구자료만 제외했으며 실행 기능은 유지합니다.

현재 상태
이 폴더는 수정·검증한 웹사이트 소스입니다. 운영 사이트와 실제 Supabase DB는 변경하지 않았습니다.
출연진 보강·보안 권한 변경은 별도 SQL 묶음으로 전달합니다. 사용자가 직접 실행하도록 준비했습니다.
로컬 미리보기에는 SQL 적용 전 자료가 들어 있으므로 새 배우 정보는 아직 보이지 않는 것이 정상입니다.

1. 화면 변경
• 매체별 인기 작품: 웹툰 → 드라마·OTT → 영화 → 웹소설, 각 5개, 화면 번호 1~5.
  기존 번호는 공식 플랫폼 순위였고, 애니메이션·성인·미연결 항목을 제외하면서 중간 번호가 빠졌습니다.
  새 번호는 표시 순번입니다. 전체 플랫폼 통합 인기 순위라는 의미가 아니며 원순위·기간·출처는 따로 보존합니다.
  OTT는 기존 시즌 ID와 작품 ID 불일치로 전체 탭이 빠졌습니다. 판본을 확인한 공식 링크로 연결합니다.
  DB와 정확히 연결하지 못한 항목은 공식 플랫폼에서 열며 새 DB 작품을 임의 생성하지 않습니다.
• 플랫폼: 넷플릭스, 네이버웹툰, 네이버시리즈, 카카오페이지, 티빙, 리디, U+tv모바일,
  웨이브, 왓챠, 쿠팡플레이, 애플TV, 디즈니+, 카카오웹툰의 13개 서비스로 고정합니다.
  ‘네이버 시리즈’는 네이버시리즈, ‘Apple TV’는 애플TV로 합쳐 작품 수를 중복 없이 계산합니다.
  목록 밖 서비스는 필터·상세 감상처에서 제외합니다. DB의 원본 플랫폼과 출처는 지우지 않습니다.
  이번 작업이 모든 작품의 모든 플랫폼 제공 여부를 새로 조사한 것은 아닙니다.
• 같은 제작진: 확인된 인물 연결이 있는 작품만 표시하고, 연결이 없으면 영역 자체를 숨깁니다.
  ‘같은 이름의 작가로 찾은 작품’은 이름만 같은 후보였으므로 동명이인 오연결 위험을 줄이기 위해 표시하지 않습니다.
• 메인 주소: 검색·필터·상세 이용 중에는 / 주소를 유지합니다. 뒤로 가기와 탭 안 새로고침 상태는 보관합니다.
  이로 인해 주소 복사만으로 특정 필터·작품을 다른 사람에게 공유할 수는 없습니다.
  로그인 처리에 필요한 콜백 주소와 별도 /taste/ 페이지는 강제로 /로 바꾸지 않습니다.
• 광고: 작품 장면·캐릭터 없는 추상 배경으로 교체하고 문구는 실제 HTML 글자로 표시합니다.
  ‘웹툰’ 글자 오류를 없앴으며 두 광고가 32KB 이미지 하나를 공유합니다.

2. DB SQL부터 직접 적용
별도 DB 묶음의 00_적용순서.txt와 04_보안검토_결과와_적용순서.txt를 먼저 읽으세요.
기존 DB를 백업한 후 올바른 Supabase 프로젝트에서 아래 순서로 진행합니다.
① 05_출연배우_적용전후검증.sql로 현재 상태를 확인하고 결과를 저장합니다.
② 01_출연배우_보강_증분.sql을 전체 실행합니다. 기존 작품 삭제/전체 교체 SQL이 아닙니다.
③ 05_출연배우_적용전후검증.sql을 다시 실행하여 배치 결과를 확인합니다.
④ 02_보안_우선적용_불필요권한회수.sql은 보안 보고서를 확인한 후 별도로 실행합니다.
⑤ 03_보안_권고_새객체기본권한검토.sql은 향후 객체 권한에 영향을 주므로 담당자가 검토한 뒤 선택 적용합니다.
06_출연배우_이번보강만_되돌리기.sql은 문제가 있을 때만 쓰는 되돌리기 파일입니다. 정상 적용 직후 실행하지 마세요.
SQL이 기존 자료 변경을 감지해 중단하면 보호 검사를 제거하지 말고 현재 DB와 다시 대조하세요.

3. GitHub와 Vercel 적용
• 배포 ZIP을 압축 해제하고 api/public/scripts/server와 package.json/vercel.json 등 내용물을
  기존 GitHub 저장소 최상위에 올립니다. ZIP 자체나 바깥 폴더 하나를 올리면 안 됩니다.
• DB SQL 묶음, 출처 조사자료, .env.local, DB 비밀번호, secret/service_role 키는 공개 저장소에 올리지 않습니다.
  배포 ZIP에 이 비밀 설정은 들어 있지 않습니다. .env.example은 값이 없는 설정 예시입니다.
• 기존 chalpick.kr 프로젝트를 유지합니다. Root Directory ./, Framework Other,
  Build Command npm run build, Output Directory dist, Node.js 24.x를 사용합니다.
• Production 환경의 SUPABASE_URL 및 SUPABASE_PUBLISHABLE_KEY는 기존 올바른 값을 유지합니다.
  로그인용 Secret 등 기존 환경변수를 삭제하지 않습니다. 새 프로젝트를 만들 필요가 없습니다.
• DB SQL 적용 후 새 코드로 배포하거나 최신 배포를 Redeploy합니다. 빌드에서 DB를 다시 읽어야 배우가 보입니다.
  새로고침만으로 DB 변경이 반영되는 구조가 아닙니다.
• 최종 Ready 배포에서 고수의 빈 연결 영역 숨김, 거룩한 밤/범죄도시의 배우,
  인기 탭 4개×5편, 플랫폼 13개, 주소 유지, 새 광고를 확인합니다.
• 공급자 연결 없는 로컬 미리보기에서는 실제 OAuth 로그인을 검증하지 않았습니다.

4. 보안과 권리의 한계
XSS 방어 출력 처리, 보안 헤더, 입력·외부 응답 제한, 비공개 파일 노출 방지를 보강했습니다.
DB 쓰기 권한과 소유자 정책을 읽기 전용으로 점검하고 불필요 권한 회수안을 분리했습니다.
해킹 불가능이나 외부 침투 시험·보안 인증을 의미하지 않습니다. 계정 MFA·접근권한·배포 로그도 관리해야 합니다.
광고는 제3자 작품 이미지를 입력하지 않고 새로 생성했지만 저작권 위험 0%를 보증할 수는 없습니다.
공식 작품 포스터 URL을 안다는 것이 상업적 재게시 허락을 받았다는 뜻도 아닙니다.
출시 전 포스터·로고 이용조건은 별도로 확인하세요. 생성 기록과 범위는 PROMO_ASSETS.md에 있습니다.

5. 로컬 확인
미리보기.cmd를 실행하면 기본 http://localhost:4174/ 에서 v7을 확인합니다.
기존 http://localhost:4173/ 는 이전 버전일 수 있습니다.
첫 화면 사전 렌더링과 단일 CDN 카탈로그 방식은 유지합니다. 실제 속도는 운영 배포 후 별도 측정해야 하며
모든 방문자의 첫 화면·전체 검색 준비가 1초 안에 끝난다고 보장하지 않습니다.
