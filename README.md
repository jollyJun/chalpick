# 찰픽 메인페이지 개선 v7

## GitHub 웹 업로드용 — 97파일

이 묶음은 GitHub 브라우저 업로드 100파일 제한에 맞춘 배포용입니다. 전체 개발 원본은 변경하지 않았으며 테스트·일회성 조사 스크립트와 미사용 예전 자료만 제외했습니다. 화면·검색·API·서버·빌드 기능은 전체 v7과 같습니다. 테스트 162개는 전체 원본에서 수행한 결과이며, 이 묶음의 package.json에서는 제외된 테스트 명령만 제거했습니다.

ZIP을 풀고 **안의 내용물 전체**를 저장소 최상위의 Upload files에 한 번에 넣습니다. ZIP 자체나 바깥 폴더 한 개를 업로드하지 않습니다. 이전 100개 초과 업로드 화면은 저장하지 말고 새로 시작하세요. 실제 사용한 API 키나 .env.local, 별도 SQL 자료를 섞지 마세요. 아래 개발·검증 이력 중 테스트 명령은 전체 개발 원본에서 실행하는 명령입니다.

## v7 적용 안내 — 2026-10-23

현재 변경사항과 SQL 적용·배포 순서는 `v7_적용안내.txt`를 먼저 확인하세요. 실제 Supabase와 운영 사이트는 이번 작업에서 수정하지 않았습니다. DB 업데이트 SQL은 별도 전달하며 GitHub 공개 저장소에 올리지 않습니다.

- 인기 작품은 웹툰 → 드라마·OTT → 영화 → 웹소설 순서로 각 5개를 표시합니다. 화면 번호 1~5와 출처의 원순위를 분리합니다.
- 플랫폼은 지정된 13개 서비스로 고정하고 네이버 시리즈·Apple TV 등 별칭은 합칩니다. DB의 원본 플랫폼 근거는 삭제하지 않습니다.
- 확인된 인물 연결이 없으면 같은 작가·감독 영역을 숨깁니다. 동명이인을 혼동할 수 있는 이름만 일치하는 영역은 표시하지 않습니다.
- 메인 페이지의 필터·상세 상태는 주소 대신 브라우저 기록과 세션에 보관합니다. 로그인 콜백과 별도 `/taste/` 경로는 유지합니다.
- 광고는 특정 작품의 장면·인물 없는 추상 이미지와 실제 HTML 문구로 교체했습니다. 권리 검토 범위는 `PROMO_ASSETS.md`에 기록했습니다.
- 서버 보안 헤더·외부 응답 크기 제한·입력 검증·로컬 파일 보호를 보완했습니다. 완전한 보안 보증이나 외부 침투 시험을 의미하지 않습니다.

## 첫 화면을 먼저 보여주는 구조 — 2026-10-23

방문할 때마다 10,170편을 21번 나누어 조회한 뒤 화면을 그리던 방식을 바꿨습니다. **운영 배포를 빌드할 때 Supabase 전체 자료를 검증하고, 실제 추천 작품과 정확한 전체 수를 HTML에 미리 넣습니다.** 브라우저는 이 화면을 먼저 표시한 뒤 전체 검색 자료를 CDN 파일 한 번으로 받아 검색을 준비합니다. 과거 2,500편 자료나 일부 25편만으로 전체 검색 결과를 계산하지 않습니다.

첫 화면용 작품 정보는 현재 배포 자료에서 25편이며, 초기 HTML에 포함되는 상한은 40편입니다. 전체 공개 대상 10,170편, 탐색 9,962편, 확인된 성인 제외 208편의 수치는 전체 자료에서 계산합니다. 상단 공식 표지 12개는 출처 URL과 작품 ID를 대조한 경량 WebP로 준비했고, 두 광고 자리에는 찰픽 홍보 이미지를 넣었습니다.

**DB 변경은 다음 성공한 빌드·재배포부터 반영됩니다.** 방문 시점의 실시간 DB 조회가 아니라 생성 시각이 명시된 검증된 배포본입니다. DB 조회 실패나 수량 불일치가 있으면 운영 빌드를 중단하며, 이전 파일로 몰래 배포하지 않습니다. 사이트 표시와 전체 검색 준비는 서로 다른 단계이므로 모든 기기·회선에서 1초 완료를 보장하지 않습니다. 배포 절차는 [배포_및_속도개선_안내.md](배포_및_속도개선_안내.md), 구조와 설정은 [CATALOG_SETUP.md](CATALOG_SETUP.md)를 참고하세요.

화면은 DB 공개 대상 수, 실제 탐색 수, 확인된 성인 제외 수를 구분합니다. 미확인 이용등급은 전체이용가로 간주하지 않습니다. DB의 기념일·계절·날씨 태그도 함께 읽습니다. 과거 전체 교체 SQL을 다시 실행하거나 RLS를 끌 필요가 없습니다. 이번 출연진 보강만 별도 증분 SQL로 적용합니다.

기준일: 2026-10-23. 기존 페이지와 데이터 파일을 보존하고 별도 폴더에서 제작한 찰픽 메인페이지입니다. 흰색 중심의 반응형 화면에 작품 탐색, 취향 추천, 상세 정보, 실제 플랫폼 인기순위를 구성했습니다.

## 실행

Node.js 24를 사용합니다. 프로젝트 폴더에서 다음을 실행합니다. 추가 npm 패키지는 필요하지 않습니다.

```sh
npm run dev
```

`npm run dev`의 기본 주소는 `http://localhost:4173`입니다. Windows의 `미리보기.cmd`는 옛 버전과 충돌하지 않도록 기본 `http://localhost:4174`에서 v7을 엽니다. 환경변수 없는 로컬 실행은 동봉된 검증된 배포 자료를 사용하며 새 DB 조회가 아닙니다. OAuth 로그인까지 시험할 때는 실제 포트에 맞춘 출처·콜백 설정을 사용하고 `localhost`와 `127.0.0.1`을 혼용하지 마세요. [AUTH_SETUP.md](AUTH_SETUP.md)를 참고하세요.

## 화면 사용법

1. 상단 검색창 또는 작품 탐색 안의 검색창에 제목·제작진·키워드를 입력합니다.
2. 장르·소재와 배경·인물과 관계 탭에서 원하는 태그를 고릅니다. **장르·소재와 배경·인물과 관계에서 선택한 태그가 모두 일치(AND)**하는 작품을 찾습니다. 예를 들어 판타지·액션·모험을 고르면 세 태그를 모두 가진 작품만 나옵니다. 플랫폼은 선택한 감상처 중 하나 이상에 제공되는 작품을 찾습니다. 선택한 조건을 개별 해제하거나 필터 초기화를 사용할 수 있습니다.
   태그 옆 숫자는 현재 결과에 포함된 작품 수입니다. 결과가 없는 미선택 태그는 흐리게 표시하고 선택을 막습니다. 이미 선택한 0개 태그는 해제할 수 있습니다. 매체 변경 시 검색어·태그·플랫폼 조건을 유지합니다.
3. 취향순·공개연도순·가나다순으로 정렬하고 ‘작품 더 보기’로 결과를 이어 봅니다. 공개연도는 업데이트 날짜와 다른 값입니다.
4. 작품 표지나 제목을 누르면 상세 정보를 봅니다. 공식 감상처 링크는 제공자 페이지를 새 창으로 열며, 책갈피 버튼은 내 보관함에 저장합니다.
5. 임시 취향 표시 또는 탐색 영역의 취향 요약을 눌러 좋아하는 키워드를 쉼표로 구분해 변경합니다. ‘임시 취향으로 되돌리기’는 아래 기본 프로필을 다시 적용합니다.
6. 인기 작품은 ‘웹툰’, ‘드라마·OTT’, ‘영화’, ‘웹소설’ 네 탭에서 각 5개를 제공합니다. DB에 연결되지 않았거나 판본 차이가 있는 항목은 확인된 공식 플랫폼으로 연결합니다. ‘지금 이 순간의 이야기’는 자동으로 선정한 테마 한 개를 표시하며 해당 테마 작품을 취향순으로 볼 수 있습니다.

## 임시 취향과 로그인

첫 방문의 기본 임시 프로필은 **액션파 독자 — 액션·무림·먼치킨·회귀**입니다. 저장된 다른 취향이 있으면 그 값을 유지합니다. 임시 프로필을 적용하는 것만으로 회원 계정이나 로그인 세션을 만들지 않습니다.

취향과 보관함은 현재 브라우저의 localStorage에 저장됩니다. 소셜 로그인 성공 후에도 자동으로 다른 기기에 동기화되지 않으며, Supabase 회원 행을 생성하지 않습니다. 네이버·카카오의 실제 동의 화면과 세션 처리는 별도 서버 코드가 담당합니다. 앱 자격정보가 없으면 로그인 연결이 준비되지 않은 상태로 표시합니다.

- 로그인 설정·콜백·환경변수·세션 경계: [AUTH_SETUP.md](AUTH_SETUP.md)
- 추천 계산·임시 프로필·제작진 매칭·테마 규칙: [RECOMMENDATION_RULES.md](RECOMMENDATION_RULES.md)

## 카탈로그와 추천 근거

운영 빌드에서 Supabase `contents`와 작품의 태그·감상처·제작진·복잡도 정보를 읽으며 원본 ID를 유지합니다. 500행씩 모든 페이지와 관계 자료를 검증하고 수량·ID·등급·태그 집계가 일치한 경우에만 새 배포 자료를 만듭니다. `HOLD`는 기존 공개 조회 정책에 따라 제외합니다. 방문자의 첫 화면은 이 검증을 다시 기다리지 않습니다.

초기 HTML에는 추천·몰입·탐색·인기·계절 카드와 전체 집계가 들어 있습니다. 브라우저가 전체 자료를 준비하는 동안 해당 화면을 유지합니다. 전체 검색 자료 다운로드가 실패하면 생성일 기준의 추천은 남기되 오류와 재시도를 안내하고, 초기 일부 작품을 전체 검색 목록처럼 취급하지 않습니다.

소개·연도·이미지·감상처는 DB 값을 사용합니다. 확인된 성인 작품의 원본 표지는 API에서 안내 이미지로 치환하며 현재 탐색에서는 제외합니다. 일반 표지는 공식 공급처 변경이나 로딩 실패가 발생할 수 있으며, 실패 시 작품명으로 대체합니다.

작가·제작진·배우의 크레딧은 DB의 관계 행을 함께 읽습니다. 공식 인물 ID가 같은 경우만 동일 인물 또는 명시된 창작 스튜디오로 연결합니다. 공식 ID가 없는 같은 이름의 감독·작가는 **동명 포함 후보**이며 동일 인물 확인으로 취급하지 않습니다. 여러 작가를 묶은 공동 계정은 같은 작가 추천에서 제외합니다. 화면 매체의 ‘같은 감독’에는 감독 역할만 사용합니다.

현재 메인 추천은 태그 기반입니다. 서버의 DB 조회와 검증에는 4축·서사 엔진·복잡도 정보를 포함하지만, v6의 CDN 전달 자료에서는 화면이 사용하지 않는 `recommendation`, `tagSlugs`와 불필요한 크레딧 필드를 제외해 크기를 줄입니다. 이를 현재 화면의 확정 추천 점수나 공식 플랫폼 평가로 설명하지 않습니다. 현재 메인과 기존 `/taste/`의 v16 1,700편 데이터·계산 로직은 별개이며 자동으로 같은 모델에 동기화되지 않습니다.

카탈로그는 운영 빌드 때 DB에서 조회합니다. 사이트 새로고침만으로 DB 변경이 반영되지 않으므로 변경 후 다시 배포하세요. 일반 태그는 `contents.tag_slugs_cache`와 `tag_dictionary`를 연결하므로 존재하지 않는 `content_tags` 테이블에 의존하지 않습니다. 이 연결 작업은 DB 데이터를 수정하거나 권한을 확장하지 않습니다.

인기 작품은 확인된 비성인·비애니메이션 항목을 원순위 순서로 고른 뒤 화면 번호만 1~5로 표시합니다. 이는 전체 서비스 통합 순위가 아닙니다. 원래 순위와 집계기간·플랫폼은 출처에 보존하며, 원본 집계 범위와 실제 표시 제외 기준을 나누어 안내합니다. DB에 연결되지 않은 작품은 확인된 공식 플랫폼 링크로 열고 가짜 상세정보를 만들지 않습니다. 단행본이나 특정 시즌과 전체 작품이 다르면 판본 차이를 기록합니다.

애니메이션 전용 인기 탭은 화면에서 제거했습니다. 보존된 원본 순위 파일은 변경하지 않았습니다.

KOBIS·카카오·라프텔은 이번 조회에서 충분한 공식 순위 자료를 확보하지 못해 `unavailable`과 사유를 기록했습니다. 카탈로그 ID 순서나 편집자의 선택을 실시간 인기로 대신 표시하지 않습니다.

Python 3가 있는 환경에서 프로젝트 폴더를 기준으로 다음을 실행합니다.

```sh
# 공식 페이지를 다시 조회하고 popular.json과 근거 보고서를 갱신
python scripts/update-popular.py

# 이미 저장한 근거로만 다시 생성. 최신 순위를 조회하는 명령은 아님
python scripts/update-popular.py --cached
```

**예약 갱신은 설정되어 있지 않습니다.** 새 자료를 운영 화면에 반영하려면 갱신 결과를 검토한 뒤 다시 빌드·배포해야 합니다. 공식 페이지 구조가 바뀌면 수집기를 수정해야 할 수 있습니다.

## 자동 테마 추천

- 작품별 태그는 DB의 `anniversary_tags`, `season_tags`, `weather_tags`에서 읽습니다. 한 작품에 여러 태그를 사용할 수 있으며 일반 장르로부터 임의 추정하지 않습니다. 추천 근거 원장은 별도 콘텐츠 자료에 보존합니다.
- 계절과 기념일 날짜는 Asia/Seoul 기준입니다. 한국 기념일의 앞뒤 7일을 모두 포함하며, 겹치는 기념일은 기념일 추천 차례마다 돌아가며 표시합니다. 설날·추석 날짜는 공식 월력요항으로 확인한 2025–2027년 표를 사용합니다. 이후 연도의 공식 발표를 확인해 표를 갱신해야 합니다.
- 방문자가 페이지를 새로 열거나 새로고침할 때 한 번 선정하고, 페이지 안에서 필터·취향을 변경해도 테마를 다시 추첨하지 않습니다. 같은 브라우저의 누적 방문에서 날씨 6 : 기념일 3 : 계절 1을 적용합니다. 날씨+계절은 6:1, 기념일+계절은 3:1이며 계절만 있으면 항상 계절을 표시합니다. 실제 추천 작품이 없는 종류는 제외합니다.
- 추천 순환 상태는 브라우저에 저장합니다. 저장을 차단하거나 다른 브라우저를 쓰면 이전 방문과의 교대 기록을 이어갈 수 없습니다.
- 날씨는 Vercel 접속 지역을 자동 감지하여 MET Norway의 현재 시간대 1시간 예보를 조회합니다. GPS 권한이나 날씨 API 키는 필요 없습니다. 비·폭풍과 눈만 적용하고, 조회 실패나 지역 미확인 시 나머지 추천으로 이어집니다. localhost에서는 지역을 확인할 수 없으므로 계절·기념일을 보여줍니다. 자세한 운영 사항은 [WEATHER_SETUP.md](WEATHER_SETUP.md)를 참고합니다.
- 초기 HTML은 자료 생성 시점의 계절 추천을 명시해서 먼저 보여줍니다. 전체 자료가 준비된 뒤 실제 방문 시점의 한국 날짜·접속 지역 날씨로 기존 테마 선정 규칙을 적용합니다. 날씨 조회 때문에 첫 화면 표시를 기다리지 않습니다.
- 주제 배경과 미리보기 작품도 선정한 테마에 맞춥니다. 테마 태그를 표시·관리하는 화면은 제공하지 않습니다. DB 컬럼을 수정하면 다음 성공한 빌드·재배포에 반영됩니다.

## 빌드와 Vercel 배포

```sh
npm run check
npm test
npm run build
```

Vercel 설정은 Framework Preset `Other`, Build Command `npm run build`, Output Directory `dist`, Node.js `24.x`입니다. 프로젝트 루트는 이 README가 있는 폴더입니다. **`api/`, `public/`, `scripts/`, `server/`, `package.json`, `vercel.json`이 저장소 최상위에 있도록 프로젝트 내용물을 올립니다.** ZIP 파일 자체나 바깥 폴더 하나만 올리거나 `dist/`만 배포하지 않습니다. 운영 빌드에는 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`가 필요하고 실제 로그인에는 [AUTH_SETUP.md](AUTH_SETUP.md)의 서버 환경변수가 별도로 필요합니다. `.env.local`, 비밀 키, DB 비밀번호는 업로드하지 않습니다.

v7 로컬 빌드 완료를 `chalpick.kr` 운영 반영 완료로 해석하지 않습니다. DB SQL을 직접 적용한 뒤 GitHub 업로드와 Vercel 새 배포를 해야 출연진 보강도 반영됩니다. 실제 운영 주소에서 작품 표시·검색·필터·이미지·DB 반영일을 확인하세요. 기존 Vercel 프로젝트와 도메인을 유지합니다.
